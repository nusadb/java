# nusadb-hibernate6: Hibernate ORM 6.x dialect for NusaDB

A thin [Hibernate ORM](https://hibernate.org/) 6.x dialect layered on the
[`nusadb-jdbc`](../README.md) driver. Built against Hibernate **6.6** (what Spring Boot 3.4 and 3.5
ship) and tested on **6.4** and **6.6**, with Java 17. HQL upsert needs Hibernate 6.5 or later;
everything else works from 6.4.

## Usage

```properties
hibernate.connection.url = jdbc:nusadb://user@host:5678/nusa
```

The URL is enough: the driver registers itself with `DriverManager`, and Hibernate picks
`NusaDialect` from the product name the connection reports (`NusaDB`). Setting
`hibernate.dialect = com.nusadb.hibernate.NusaDialect` explicitly still works.

The dialect maps JDBC types to the column types NusaDB accepts (`int`, `bigint`,
`smallint`, `boolean`, `real`, `double precision`, `numeric(p,s)`, `text`, `date`,
`time`, `timestamp`, `varbinary`) and renders pagination (`setMaxResults` /
`setFirstResult`) as a constant `LIMIT`/`OFFSET` with inlined literals.

Booleans are rendered as `true`/`false` (so `findByActiveTrue` and `cb.isTrue` work), and
`java.util.UUID` maps to the native `uuid` column type.

### HQL functions

Besides the standard HQL functions, the dialect renders these the way the server expects:
`locate()`/`position()`, `trim()`, `extract(day of week|day of month|day of year ...)`, datetime
arithmetic (`e.at + 1 day`, `(a - b) by day|hour|month|year ...`), `truncate(datetime, month)`,
`listagg(x, ',') within group (order by ..)`, `local time`, and date/time literals (`{d '..'}`,
`{ts '..'}`, `local date ..`) as typed SQL literals. `HqlFunctionIT` covers them.

### HQL features

The dialect turns on what the server runs natively, so Hibernate does not emulate it:

- window functions: `row_number()`, `rank()`, `dense_rank()`, `lag()`/`lead()`, `first_value()`,
  `ntile()`, aggregates `over (partition by .. order by .. rows between ..)`;
- aggregates: `every()`/`any()`, `stddev*()`, `var*()`, `covar_*()`, `corr()`, `regr_*()`,
  `median()`, `percentile_cont`/`percentile_disc`/`mode()` and hypothetical `rank(x)`
  `within group (order by ..)`, `array_agg()`, `count(*) filter (where ..)`, `group by rollup/cube`;
- functions: `ascii`, `chr`, `initcap`, `overlay`, `insert`, `translate`, `substr`, `md5`,
  `repeat`, `log`, `log10`, `cbrt`, `pi`, `degrees`/`radians`, `cot`, hyperbolic functions,
  `bitand`/`bitor`/`bitxor`/`bitnot`, `make_date`/`make_time`/`make_timestamp`, `to_char` formats;
- arrays: `array(..)`, `array_length`, `array_contains`, `array_position(s)`, `array_append`,
  `array_concat`, `array_to_string`, slices and element access, and `java.sql.Array` attributes
  (`element[]` columns);
- queries: `with` (CTEs, also `recursive` and joined), `join lateral (..)`, `union`/`intersect`/
  `except` (also inside `in (..)` subqueries), `is distinct from`, `ilike`,
  `fetch first n rows with ties`, row-value comparisons;
- `insert ... select` (ids from the entity's sequence) and, on Hibernate 6.5+, upsert:
  `insert ... on conflict (..) do update set .. / do nothing`;
- lock options: `jakarta.persistence.lock.timeout` 0 is `FOR UPDATE NOWAIT` and -2 is
  `FOR UPDATE SKIP LOCKED`; a lock that cannot be taken raises `PessimisticLockException`.

`HqlFunctionIT` and `BulkMutationIT` cover the rendering on the server.

### Identifiers

Every `@GeneratedValue` strategy works:

| Strategy | Schema | How the id is obtained |
|---|---|---|
| `IDENTITY` | `id bigint generated by default as identity` | returned by the INSERT (`getGeneratedKeys`) |
| `SEQUENCE` | `create sequence ... start with 1 increment by <allocationSize>` | `select nextval('...')`, one call per block of `allocationSize` ids |
| `AUTO` (the default) | a sequence named `<table>_seq`, as `SEQUENCE` | as `SEQUENCE` |

`ddl-auto=validate` and `update` read the existing sequences from `information_schema.sequences`.

**Upgrading from 0.2.x with `AUTO` or `SEQUENCE` ids.** Earlier versions emulated sequences with a
table named after the sequence (one `next_val` row). From 0.3.0 a real sequence is used, and a new
sequence starts at 1, below the ids already in the table. Before starting the upgraded application,
create each sequence so that its first value is at least the highest id plus the `allocationSize`
(the pooled optimizer hands out the block of ids *below* each value it reads), for example:

```sql
SELECT max(id) + 50 + 1 FROM product;                          -- say 1051
CREATE SEQUENCE product_seq START WITH 1051 INCREMENT BY 50;   -- may share the old table's name
```

### Bulk UPDATE and DELETE

An HQL `update` or `delete` whose `where` navigates to another entity
(`update Product p set p.price = p.price * 2 where p.category.name = :c`) is rendered with an
uncorrelated `id in (select ...)` subquery, which the server runs. An entity with a composite id
cannot use this form yet.

### Schema and errors

`hbm2ddl.auto=create` and `create-drop` work on a fresh database, also with
`hibernate.hbm2ddl.halt_on_error=true`: tables are dropped with `drop table if exists ... cascade`
and foreign keys with `alter table if exists ... drop constraint if exists`. A unique, foreign key or
check violation raises Hibernate's `ConstraintViolationException` with the constraint name the
server reports in `getConstraintName()`.

### Bootstrap

Hibernate reads the connection's `DatabaseMetaData` at boot to choose the dialect, which
`DialectResolutionIT` covers together with `create-drop`. Since 0.3.0 the default
`hibernate.boot.allow_jdbc_metadata_access=true` works; set it to `false` to boot without
connecting, and then `hibernate.dialect` is required.

## Build & test

From the repository root (see the [root README](../README.md#build--test) for how the
integration tests find a server):

```bash
mvn verify -Pit -pl hibernate6 -am
```

Add `-Phibernate-6.4` to run the same tests on Hibernate 6.4 instead of 6.6.

`GeneratedIdIT` covers the `IDENTITY`, `SEQUENCE` and `AUTO` strategies and schema validate/update
over them. `HibernateIT` exercises schema export, persist/load, update, a query with a row limit,
delete, and transaction rollback.
